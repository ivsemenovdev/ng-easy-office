# Документация для AI-агентов

Каталог предназначен для машиночитаемых спецификаций и контекста проекта **ng-easy-office**.

## Обязательные правила

**Все изменения нужно документировать.** Код, миграции и сиды без актуальной документации считаются незавершёнными.

| Что изменили                              | Где зафиксировать                                                                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Схема БД, сиды, запросы                   | Соответствующий файл в `docs/ai/` (например, [database-regions.md](./database-regions.md)): описание, DDL/примеры, **таблица истории** в конце документа |
| Новая подсистема / домен                  | Новый `docs/ai/<тема>.md` + строка в таблице «Файлы» ниже                                                                                                |
| Скрипты генерации, пути к артефактам      | Тот же доменный документ и § «Связанные файлы»                                                                                                           |
| Поведение API, контракты (когда появятся) | Доменный документ или отдельная спецификация в `docs/ai/`                                                                                                |
| Политика БД, роли, миграции               | [database-policy.md](./database-policy.md)                                                                                                               |
| REST API (Node.js)                        | [api-backend.md](./api-backend.md)                                                                                                                       |

Минимум при каждом изменении:

1. Обновить текст спецификации (не только комментарии в SQL/TS).
2. Добавить строку в **историю изменений** документа (дата, кратко — что и зачем).
3. При смене статуса (миграция применена, сид добавлен) — обновить блок **«Статус»** в начале документа.
4. Если правило общее для проекта — отразить его здесь, в `docs/ai/README.md`.

**Для AI:** перед завершением задачи проверить, что документация в `docs/ai/` соответствует фактическому состоянию репозитория.

## Проект

- **Фронтенд:** Angular 21, Taiga UI — корень репозитория `src/`.
- **БД (локально):** PostgreSQL, база `donetsk_test`.
- **SQL-миграции:** `database/migrations/`.

При работе с БД: [database-policy.md](./database-policy.md) → доменный документ в `docs/ai/` → миграция/сид → обновить документацию и историю → `./database/scripts/migrate.sh`.
